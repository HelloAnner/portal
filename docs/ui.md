# 门户系统 UI 设计说明

## 1. 设计目标

门户系统是企业内部系统的统一入口，也是统一身份、租户、角色、权限和子系统接入配置的控制面。页面设计需要同时服务两类人：

- 普通用户：登录后快速看到自己可进入的系统，点击后自动进入目标子系统。
- 管理员：既能像普通用户一样进入业务系统，也能进入门户后台配置用户、租户、系统、角色、权限和审计。

门户不做 Northline、DocuMind 等子系统的业务管理页复刻，只负责配置和下发用户在不同子系统、不同租户、不同角色层级下的身份上下文。

## 2. 视觉与交互风格

视觉风格参考 `/Users/anner/Northline/DESIGN.md`，采用克制、低噪音、高信息密度的企业控制面风格。

### 2.1 设计原则

- 单色为主：主操作、选中态、激活态使用黑白反相，不使用彩色按钮或大面积品牌色。
- 层级清晰：通过背景层级、发丝边框和留白区分页面区域，不使用装饰性阴影。
- 信息密度优先：后台页面以表格、行式列表、抽屉和紧凑表单为主。
- 彩色只表达状态：绿色、红色、琥珀色、蓝色仅用于成功、错误、警告、信息提示。
- 动效克制：悬停、抽屉、模态使用 150ms 到 300ms 的短过渡，不使用弹性或夸张动画。

### 2.2 基础布局

- 用户门户页使用顶部栏 + 主内容区。
- 管理后台使用左侧导航 + 顶部上下文栏 + 内容区。
- 编辑、授权、配置详情优先使用右侧抽屉。
- 创建类、批量类、高风险确认使用居中模态。
- 数据密集页面使用表格和行式列表，不使用大块装饰卡片。

### 2.3 核心组件

- 系统入口卡片：展示系统图标、名称、描述、当前身份、租户范围、状态和进入按钮。
- 身份徽标：展示普通用户、租户管理员、超级管理员等身份。
- 租户切换器：用于用户属于多个租户时切换当前进入上下文。
- 权限矩阵：按用户、租户、系统、角色层级展示最终授权结果。
- 右侧抽屉：用于用户详情、系统详情、角色详情、租户详情、审计详情。
- 批量操作栏：表格多选后出现，用于批量启用、禁用、授权、撤销。

## 3. 信息架构

门户页面分为用户态和管理态。

```text
登录
  └─ 门户首页
       ├─ 系统入口
       ├─ 我的资料
       ├─ 我的权限
       └─ 管理后台
            ├─ 概览
            ├─ 用户管理
            ├─ 租户管理
            ├─ 系统目录
            ├─ 权限配置
            ├─ 子系统管理员
            ├─ 子系统接入
            └─ 安全与审计
```

普通用户默认只看到门户首页、我的资料和我的权限。门户超级管理员、系统接入管理员或授权管理员可看到管理后台入口。

## 4. 角色与身份表达

门户需要区分门户身份和子系统身份。

### 4.1 门户身份

- 门户普通用户：只访问被授权系统和个人资料。
- 门户超级管理员：管理所有用户、租户、系统、权限、接入和审计。
- 门户配置管理员：可按职责扩展，例如只管理系统目录或只管理审计。

### 4.2 子系统身份

每个子系统都支持三层身份：

- 普通用户：可进入系统并使用被授权的业务功能。
- 租户管理员：在指定租户范围内管理该子系统的用户、资源或配置。
- 超级管理员：在该子系统范围内拥有全局管理能力，由门户配置并下发，不由子系统在托管模式下单独定义。

同一个用户可以在不同子系统、不同租户拥有不同身份。例如：在 Northline 的 A 租户是租户管理员，在 DocuMind 的 B 租户是普通用户。

## 5. 页面设计

### 5.1 登录页

#### 作用

提供门户统一登录入口。用户只在门户登录一次，后续进入 Northline、DocuMind 等托管子系统时不再重复登录。

#### 页面内容

- 企业门户名称。
- 登录表单：账号、密码、记住登录状态。
- 登录方式扩展位：企业 SSO、LDAP、OAuth。
- 异常提示：账号禁用、密码错误、会话过期。

#### 交互

- 登录成功后进入门户首页。
- 已登录用户访问登录页时自动跳转门户首页。
- 子系统凭证过期跳回门户时，登录成功后回到原目标系统。

#### 视觉

登录页可以比后台页面留白更大，但仍保持单色风格。主按钮使用反相样式，错误文案使用语义红。

### 5.2 门户首页

#### 作用

普通用户和管理员共同使用的系统入口页。用户在这里选择要进入的子系统。

#### 页面内容

- 顶部栏：门户名称、当前用户、头像、租户切换器、管理后台入口。
- 系统分组：常用系统、全部系统、维护中系统。
- 系统入口卡片：
  - 系统图标。
  - 系统名称。
  - 系统说明。
  - 当前用户在该系统中的身份。
  - 当前租户或可用租户数量。
  - 系统状态。
  - 进入按钮。
- 空状态：当前用户暂无可访问系统。

#### 交互

- 点击系统卡片或进入按钮后，门户生成短时凭证或一次性授权码，并自动跳转目标子系统。
- 用户属于多个租户时，点击进入前可选择租户；若只有一个租户则直接进入。
- 维护中或停用系统展示状态，不允许进入。
- 管理员在首页仍然看到自己可进入的业务系统，同时顶部栏显示管理后台入口。

#### 视觉

系统卡片使用紧凑卡片布局，卡片之间间距 12px 到 16px。身份和状态使用小徽标，不使用大面积色块。

### 5.3 我的资料页

#### 作用

允许用户查看和维护自己的显示信息，支持自定义显示名称、头像等个性化内容。

#### 页面内容

- 基础信息：
  - 用户名。
  - 显示名称。
  - 邮箱。
  - 手机号。
  - 所属组织。
  - 账号状态。
- 头像设置：
  - 当前头像。
  - 上传头像。
  - 恢复默认头像。
- 偏好设置：
  - 默认进入租户。
  - 默认首页分组。
  - 是否显示不可访问系统申请入口。

#### 交互

- 显示名称支持即时校验，保存后同步到门户首页和子系统身份上下文。
- 头像上传后进入裁剪模态，确认后保存。
- 邮箱、手机号等敏感字段可根据企业策略只读或需要管理员审核。

#### 视觉

使用左右两栏：左侧头像和账号摘要，右侧为行式表单。保存按钮固定在表单底部或抽屉底部。

### 5.4 我的权限页

#### 作用

让用户理解自己可以进入哪些系统、属于哪些租户、在各子系统中是什么身份。

#### 页面内容

- 当前门户角色。
- 所属租户列表。
- 可访问系统列表。
- 每个系统的身份：
  - 普通用户。
  - 租户管理员。
  - 超级管理员。
- 管理范围：
  - 系统级。
  - 租户级。
  - 模块级。
  - 资源级。
- 权限不足的申请入口。

#### 交互

- 点击某个系统权限行，打开权限详情抽屉。
- 权限详情展示该权限来自用户直配、角色继承还是租户授权。
- 无权限系统可以隐藏；若企业开启申请流程，则展示申请按钮。

#### 视觉

使用行式列表和小徽标表达权限来源。避免复杂图表，重点让用户能快速确认自己的最终权限。

### 5.5 管理后台概览页

#### 作用

为管理员提供门户运行状态和近期风险的入口。

#### 页面内容

- 关键指标：
  - 用户总数。
  - 启用系统数。
  - 接入门户托管认证的系统数。
  - 最近 24 小时进入子系统次数。
  - 高风险权限变更次数。
- 待处理事项：
  - 未完成接入的系统。
  - 即将失效的管理员授权。
  - 失败的凭证校验。
  - 异常登录。
- 最近审计记录。

#### 交互

- 点击指标跳转到对应列表。
- 点击待处理事项进入相关详情抽屉或配置页。
- 高风险事件使用确认态，但不在概览页直接执行危险操作。

#### 视觉

指标使用 Stat 卡片，列表使用发丝分隔线。色彩只用于异常状态点。

### 5.6 用户管理页

#### 作用

维护企业用户、账号状态、基础资料、门户角色、所属租户和可访问子系统。

#### 页面内容

- 用户表格：
  - 用户名。
  - 显示名称。
  - 邮箱。
  - 所属组织。
  - 账号状态。
  - 门户角色。
  - 所属租户数量。
  - 可访问系统数量。
  - 最近登录时间。
- 筛选：
  - 状态。
  - 门户角色。
  - 租户。
  - 系统。
  - 组织。
- 操作：
  - 新建用户。
  - 编辑用户。
  - 启用或禁用。
  - 重置认证信息。
  - 配置租户。
  - 配置权限。

#### 交互

- 点击用户行打开用户详情抽屉。
- 用户详情抽屉包含资料、租户、系统权限、子系统身份、审计记录四个标签页。
- 批量选择用户后出现批量启用、禁用、授权、移出租户等操作。
- 禁用用户时需要二次确认，并提示该用户无法进入任何门户托管子系统。

#### 视觉

主体为高密度表格。详情和编辑放入右侧抽屉，避免跳页打断管理员工作流。

### 5.7 租户管理页

#### 作用

配置门户中的租户，以及用户与租户、系统与租户之间的关系。

#### 页面内容

- 租户表格：
  - 租户名称。
  - 租户编码。
  - 状态。
  - 成员数量。
  - 已启用系统数量。
  - 租户管理员数量。
  - 创建时间。
- 租户详情：
  - 基础信息。
  - 成员列表。
  - 可用系统。
  - 每个系统中的租户管理员。
  - 资源范围说明。

#### 交互

- 点击租户打开详情抽屉。
- 在租户详情中可添加成员、移除成员、配置用户在该租户内的系统身份。
- 停用租户前需要提示该租户下所有系统访问将被阻断。

#### 视觉

租户详情使用分组行式布局。成员和系统授权列表保留表格密度，避免多层卡片嵌套。

### 5.8 系统目录页

#### 作用

管理门户中展示的子系统入口，是 Northline、DocuMind 等系统的入口配置中心。

#### 页面内容

- 系统表格：
  - 系统名称。
  - 系统编码。
  - 分类。
  - 入口 URL。
  - 状态。
  - 是否门户托管认证。
  - 是否支持子管理员。
  - 最近更新时间。
- 系统配置：
  - 图标。
  - 描述。
  - 入口地址。
  - 回调地址。
  - 凭证校验方式。
  - 支持的身份层级。
  - 支持的权限声明。

#### 交互

- 新增系统使用全屏或大尺寸模态，分为基础信息、认证配置、角色声明、发布确认四步。
- 编辑系统打开详情抽屉。
- 停用系统需要二次确认，普通用户首页不再允许进入。
- 维护中系统仍可在管理员视角查看，但用户侧进入按钮禁用。

#### 视觉

系统状态使用小状态点和文本。系统图标保持单色或低饱和，不使用强品牌色破坏整体风格。

### 5.9 权限配置页

#### 作用

配置用户在门户中能看到哪些系统、能进入哪些系统，以及进入子系统后拥有什么身份和权限。

#### 页面内容

- 配置视角切换：
  - 按用户。
  - 按租户。
  - 按系统。
  - 按角色。
- 权限矩阵：
  - 用户或角色。
  - 租户。
  - 系统。
  - 可见。
  - 可进入。
  - 子系统身份。
  - 模块权限。
  - 资源范围。
- 最终权限预览：
  - 权限来源。
  - 合并后的身份声明。
  - 即将下发给子系统的上下文摘要。

#### 交互

- 勾选可见不等于可进入，二者需要独立配置。
- 子系统身份通过下拉菜单选择普通用户、租户管理员、超级管理员。
- 模块权限使用勾选列表或权限树，但默认只展开当前系统相关权限。
- 保存前展示差异预览，尤其提示新增或撤销管理员身份。
- 撤销管理员或超级管理员身份时，可选择是否立即失效已有访问凭证。

#### 视觉

权限矩阵使用紧凑表格和固定列。开关、下拉、徽标都保持小尺寸，避免页面变成大表单堆叠。

### 5.10 子系统管理员页

#### 作用

集中配置某个用户在某个子系统、某个租户或资源范围内的管理员身份。

#### 页面内容

- 子管理员列表：
  - 用户。
  - 系统。
  - 租户。
  - 管理员类型。
  - 管理范围。
  - 生效状态。
  - 生效时间。
  - 失效时间。
  - 配置人。
- 管理员类型：
  - 系统级管理员。
  - 租户级管理员。
  - 模块级管理员。
  - 资源级管理员。
- 管理范围：
  - 全系统。
  - 指定租户。
  - 指定模块。
  - 指定资源。

#### 交互

- 新建子管理员使用抽屉式向导：选择用户、选择系统、选择租户、选择身份层级、选择管理范围、确认生效。
- 系统不同，范围选择器不同。例如 Northline 可选择数据源、问数配置等模块；DocuMind 可选择知识库、文档库、RAG 配置等模块。
- 修改管理员范围后，下次进入子系统时生效；高风险撤销可立即失效凭证。

#### 视觉

身份层级使用分段控件表达普通用户、租户管理员、超级管理员。管理范围使用行式选择器，不使用彩色大卡片。

### 5.11 子系统接入页

#### 作用

配置子系统如何接入门户托管认证，以及门户如何向子系统传递身份上下文。

#### 页面内容

- 接入系统列表：
  - 系统编码。
  - 接入状态。
  - 认证模式。
  - 发行方。
  - 回调地址。
  - 公钥或校验端点。
  - 最近校验时间。
- 接入配置详情：
  - `PORTAL_MANAGED` 语义。
  - `PORTAL_AUTH_ENABLED` 语义。
  - `PORTAL_ISSUER`。
  - 凭证有效期。
  - 身份上下文字段。
  - 权限声明字段。

#### 交互

- 提供接入检查按钮，验证系统编码、回调地址、凭证校验方式是否正确。
- 展示子系统应配置的 `.env` 示例。
- 接入中系统可保存草稿，但不会出现在普通用户门户首页。
- 切换到门户托管认证前，提示子系统生产访问链路需要关闭或旁路本地登录入口。

#### 视觉

接入详情使用代码块、配置行和校验结果列表。校验成功或失败只用状态点和简短文本表达。

### 5.12 角色管理页

#### 作用

管理门户角色和角色绑定的基础权限，减少逐个用户配置的重复成本。

#### 页面内容

- 角色列表：
  - 角色名称。
  - 角色编码。
  - 角色类型。
  - 成员数量。
  - 绑定系统数量。
  - 更新时间。
- 角色详情：
  - 基础信息。
  - 成员。
  - 系统权限。
  - 租户范围。
  - 子系统身份默认值。

#### 交互

- 点击角色打开详情抽屉。
- 给角色新增系统权限时，与权限配置页共用权限矩阵组件。
- 删除角色前提示受影响用户，并要求先迁移或移除成员。

#### 视觉

角色列表不使用大型权限卡片。详情抽屉中用标签页切分成员、权限、审计。

### 5.13 安全与审计页

#### 作用

记录登录、授权、权限变更、子系统跳转、凭证签发和接入配置变更等关键行为，保证可追踪、可回溯。

#### 页面内容

- 审计表格：
  - 时间。
  - 操作人。
  - 操作类型。
  - 操作对象。
  - 操作结果。
  - 来源 IP。
  - 用户代理。
- 筛选：
  - 时间范围。
  - 操作人。
  - 操作类型。
  - 系统。
  - 租户。
  - 成功或失败。
- 审计详情：
  - 操作前数据。
  - 操作后数据。
  - 失败原因。
  - 关联请求 ID。

#### 交互

- 点击审计行打开详情抽屉。
- 支持复制审计详情和导出当前筛选结果。
- 高风险事件可以从详情跳转到对应用户、系统或权限配置。

#### 视觉

审计页保持日志查看器风格，使用等宽字体展示 JSON 差异。失败状态使用红色文本或状态点，不使用整行红色背景。

### 5.14 无权限页

#### 作用

当用户访问无权限系统、无权限管理页或凭证无效时，给出明确反馈和可恢复路径。

#### 页面内容

- 状态标题。
- 原因说明。
- 目标系统或页面名称。
- 返回门户首页按钮。
- 申请权限按钮。
- 重新登录按钮。

#### 交互

- 无系统访问权限时返回门户首页。
- 凭证过期时重新登录，并在成功后回到原目标。
- 如果企业未开启申请流程，不展示申请按钮。

#### 视觉

使用单一焦点布局，不使用插画。主按钮反相，辅助按钮透明描边。

## 6. 关键流程

### 6.1 普通用户进入子系统

1. 用户登录门户。
2. 门户读取用户所属租户、可见系统、可进入系统和子系统身份。
3. 门户首页展示可进入系统。
4. 用户选择系统。
5. 如果存在多个租户，用户选择目标租户。
6. 门户生成短时凭证或一次性授权码。
7. 浏览器跳转子系统入口。
8. 子系统校验凭证并建立访问上下文。
9. 子系统根据普通用户、租户管理员或超级管理员身份展示页面。

### 6.2 管理员配置用户权限

1. 管理员进入管理后台。
2. 打开用户管理或权限配置页。
3. 选择用户、租户和目标系统。
4. 配置可见、可进入、子系统身份和管理范围。
5. 保存前查看权限差异预览。
6. 确认后门户记录审计日志。
7. 用户下次进入子系统时收到新的身份上下文。

### 6.3 配置子系统三层身份

1. 管理员进入系统目录或子系统管理员页。
2. 选择目标系统。
3. 定义该系统支持的身份层级：普通用户、租户管理员、超级管理员。
4. 为身份层级绑定权限声明和管理范围。
5. 将身份分配给用户、角色或租户。
6. 用户进入子系统时，门户按目标系统和租户下发对应身份。

### 6.4 用户自定义资料

1. 用户进入我的资料页。
2. 修改显示名称或头像。
3. 门户校验并保存资料。
4. 门户首页立即更新展示。
5. 用户下次进入子系统时，身份上下文携带新的显示名称和头像地址。

## 7. 状态与空场景

### 7.1 系统状态

- 启用：普通用户可按权限进入。
- 停用：用户侧隐藏或显示不可进入状态，管理员可编辑。
- 接入中：仅管理员可见，用于完成接入配置。
- 维护中：用户可见但不可进入，展示维护提示。

### 7.2 用户状态

- 启用：可登录并访问授权系统。
- 禁用：不可登录，不可进入任何托管子系统。
- 待激活：可被配置权限，但不能进入系统。
- 已归档：保留审计记录，不参与授权。

### 7.3 空状态

- 无可访问系统：提示联系管理员或申请权限。
- 无租户：提示当前账号尚未加入租户。
- 无审计记录：提示当前筛选条件下暂无记录。
- 无系统接入：引导管理员新增系统。

## 8. 权限上下文展示

门户需要在管理侧提供“最终下发上下文预览”，帮助管理员确认用户点击进入子系统时会得到什么身份。

示例：

```json
{
  "userId": "u_001",
  "displayName": "张三",
  "avatarUrl": "https://portal.example.com/avatar/u_001.png",
  "tenantId": "t_acme",
  "systemCode": "northline",
  "portalRoles": ["user"],
  "systemRoles": ["tenant-admin"],
  "permissions": [
    "northline:query:use",
    "northline:datasource:manage"
  ],
  "adminScopes": [
    {
      "scopeType": "tenant",
      "scopeCode": "t_acme"
    },
    {
      "scopeType": "module",
      "scopeCode": "datasource"
    }
  ]
}
```

该预览只用于管理员理解和排查，不允许前端直接把这些字段作为可信身份传给子系统。实际跳转必须使用签名凭证或服务端换取身份上下文。

## 9. 响应式设计

门户后台以桌面端为主，最小推荐宽度为 1280px。

- 桌面端：左侧导航固定，表格完整展示。
- 窄屏端：管理导航收起为图标栏，详情抽屉宽度不超过 90vw。
- 移动端：普通用户门户首页可用，管理后台仅提供基础查看和紧急禁用能力，不承诺完整权限矩阵编辑体验。

## 10. 设计验收标准

- 普通用户登录后能清楚看到自己可进入的系统，并能一键自动进入。
- 管理员既能正常使用门户首页进入业务系统，也能进入后台配置用户、租户、系统和权限。
- 用户可自定义显示名称和头像，资料变更能进入门户身份上下文。
- 每个子系统都能配置普通用户、租户管理员、超级管理员三层身份。
- 权限配置能同时表达系统可见、系统可进入、子系统身份、模块或资源范围。
- 租户归属和租户内身份能被清晰配置和预览。
- 子系统接入页能说明门户托管认证、回调、凭证校验和本地登录旁路要求。
- 安全与审计页能追踪登录、授权、权限变更、凭证签发和子系统跳转。
- 整体视觉符合 Northline 单色、发丝边框、高密度、反相主操作的设计语言。

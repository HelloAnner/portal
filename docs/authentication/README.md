# 登录与认证

## 功能定位

登录与认证功能在门户托管模式下由门户统一提供。每个子系统可以保留自己的独立登录模块，用于独立部署或未接入门户的场景；当子系统通过配置接入门户后，生产访问链路关闭或旁路本地登录认证，用户只登录门户。

该功能域负责解决三个问题：

- 用户如何登录门户。
- 门户如何确认用户身份并维护会话。
- 用户进入子系统时，门户如何把可信身份上下文传递给子系统。
- 子系统如何通过开关在“本地独立登录”和“门户托管认证”之间切换。

## 目标

- 提供企业内部统一登录入口。
- 统一维护用户认证状态。
- 为 Northline、DocuMind 等子系统提供可信身份来源。
- 支持子系统在门户托管模式下关闭本地登录和认证逻辑。
- 保留子系统独立部署时继续使用自身登录模块的能力。
- 允许不同子系统在独立部署模式下支持不同登录方式。
- 支持用户从门户单点进入子系统。

## 登录流程

1. 用户访问门户登录页。
2. 门户完成用户认证。
3. 门户建立门户会话。
4. 门户读取用户角色、系统权限和子管理员配置。
5. 门户展示该用户可见的系统入口。
6. 用户点击进入某个子系统。
7. 门户生成短时有效的子系统访问凭证，或通过后端服务完成凭证交换。
8. 子系统校验凭证后识别用户身份。
9. 子系统根据身份上下文展示对应页面。

## 子系统直接访问处理

当用户直接访问 Northline、DocuMind 等子系统时，子系统需要根据自身 `.env` 判断是否处于门户托管认证模式。

若处于门户托管模式：

- 子系统不展示本地登录页。
- 子系统检查请求中是否存在有效门户凭证。
- 若凭证不存在、过期或无效，子系统应跳转回门户登录或门户授权入口。
- 若凭证有效，子系统使用门户传递的身份上下文初始化用户访问状态。

若未处于门户托管模式：

- 子系统可以继续展示自身登录页。
- 子系统可以继续使用自身认证模块。
- 子系统可以继续使用自身支持的登录方式，例如账号密码、企业 SSO、LDAP 或 OAuth。
- 子系统按独立部署模式维护自己的会话和访问控制。

## 子系统本地登录的开关策略

子系统本地登录模块不要求从代码层面完全删除。更准确的要求是：在门户托管认证模式下，以下能力应通过配置关闭、旁路或限制为非生产调试能力：

- 本地登录页入口。
- 本地账号密码认证入口。
- 本地超级管理员登录入口。
- 独立会话签发入口。
- 与门户身份冲突的认证中间件。

子系统仍可保留独立部署所需的本地登录认证模块。开发调试所需的本地认证绕过配置必须默认关闭，并且不能用于门户托管的生产环境。

## 身份凭证要求

门户下发给子系统的访问凭证必须满足：

- 可校验来源。
- 短时有效。
- 包含目标子系统标识。
- 包含用户基础身份。
- 包含用户在目标子系统中的角色和权限。
- 不能仅依赖可被用户篡改的 URL 明文参数。

推荐方式：

- 使用签名令牌。
- 或使用一次性授权码，由子系统后端向门户后端换取身份上下文。

## 异常处理

- 用户未登录门户：跳转到门户登录页。
- 用户无子系统权限：门户不展示入口；若直接访问，子系统展示无权限或跳回门户。
- 凭证过期：重新走门户认证或凭证刷新。
- 子系统未接入门户：按子系统自身配置决定是否允许本地登录。

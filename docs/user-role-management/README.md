# 用户与角色管理

## 功能定位

用户与角色管理是门户的核心管理能力。门户统一维护企业用户、用户状态、门户角色以及用户在不同子系统中的身份定位。

Northline、DocuMind 等子系统可以为独立部署保留各自的登录和认证用户体系。接入门户并开启门户托管模式后，生产访问链路的用户身份来源应来自门户。子系统可以保留业务资源归属、业务配置或操作记录，但这些记录应能映射到门户用户 ID。

## 用户管理范围

门户需要管理以下用户信息：

- 用户唯一 ID。
- 用户名。
- 显示名称。
- 邮箱。
- 手机号。
- 账号状态。
- 所属组织或部门。
- 门户角色。
- 可访问系统。
- 子系统管理员配置。

## 账号状态

账号状态至少包括：

- 启用。
- 禁用。
- 待激活。
- 已离职或已归档。

禁用、离职或归档用户不应继续进入任何受门户管理的子系统。

## 门户角色

门户内置基础角色包括：

- 门户超级管理员。
- 门户普通用户。
- 子系统管理员。

门户超级管理员负责全局用户、角色、权限、系统入口和子系统接入管理。

门户普通用户只能访问被授权的系统。

子系统管理员是门户分配给用户的系统级或模块级管理身份，不是子系统内部自行定义的独立超级管理员。

## 角色与权限关系

角色用于描述用户身份，权限用于描述用户可以执行的行为。

例如：

- 用户 A 是门户超级管理员，因此可以管理所有子系统权限。
- 用户 B 是 Northline 管理员，因此进入 Northline 后可以看到管理入口。
- 用户 C 是 DocuMind 普通用户，因此只能使用文档检索和问答能力。
- 用户 D 是 DocuMind 知识库管理员，因此进入 DocuMind 后可以管理指定知识库。

## 子系统用户映射

子系统使用门户用户 ID 作为用户识别依据。

在门户托管模式下，子系统不应自行生成与门户不一致的登录用户身份。若子系统需要保存用户相关业务数据，应使用门户用户 ID 作为外部用户标识。

## 管理操作

门户需要支持：

- 创建用户。
- 编辑用户基础信息。
- 启用或禁用用户。
- 配置用户门户角色。
- 配置用户可访问系统。
- 配置用户子系统管理员身份。
- 查看用户授权结果。

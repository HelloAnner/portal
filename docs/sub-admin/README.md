# 子管理员管理

## 功能定位

子管理员管理用于在门户中配置用户在某个子系统中的管理身份和管理范围。

子管理员不是子系统自己维护的超级管理员，而是门户统一授权后下发给子系统的身份定位。

## 管理范围

子管理员可以按不同粒度配置：

- 系统级管理员。
- 模块级管理员。
- 资源级管理员。
- 组织级管理员。

示例：

- 用户 A 是 Northline 系统级管理员。
- 用户 B 是 Northline 数据源模块管理员。
- 用户 C 是 DocuMind 知识库管理员。
- 用户 D 是 DocuMind 某个指定知识库的资源管理员。

## 配置内容

门户需要维护：

- 用户 ID。
- 系统编码。
- 管理员类型。
- 管理范围。
- 生效状态。
- 生效时间。
- 失效时间。
- 配置人。
- 配置原因。

## 下发给子系统

用户进入子系统时，门户需要将该用户在目标子系统中的管理员定位传递给子系统。

示例：

```json
{
  "systemCode": "northline",
  "admin": true,
  "adminType": "module",
  "adminScopes": [
    {
      "scopeType": "module",
      "scopeCode": "datasource"
    }
  ]
}
```

## 子系统侧展示

子系统根据门户传入的管理员信息决定是否展示管理入口。

例如：

- Northline 管理员看到数据源、问数配置或用户使用统计入口。
- DocuMind 知识库管理员看到知识库配置、文档上传和索引管理入口。

## 权限撤销

当门户撤销某用户的子管理员身份后：

- 门户不再下发对应管理员声明。
- 用户再次进入子系统时不再看到管理入口。
- 对于高风险场景，可以要求已有子系统访问凭证立即失效。
